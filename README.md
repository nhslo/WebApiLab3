# Лабораторная работа — Модуль 03: Dependency Injection и логирование

**CSE5032 · Разработка веб-сервисов · Модуль 03**

Цель — отделить бизнес-логику от контроллера и научиться видеть события в журнале. Контроллер получает интерфейс сервиса и логгер через DI; текущая регистрация — Scoped. При обычном запросе пишется Information, при ненайденном товаре — Warning, при исключении — Error. В Swagger покажу список и ответ 404, в терминале — соответствующие записи. Внутренние сведения исключения не отправляются клиенту.

---

## Цель

Применить DI, интерфейс сервиса, `ILogger<T>` и разные уровни журналирования в ASP.NET Core Web API для управления товарами.

## Краткий отчёт

`ProductService` реализует `IProductService` и хранит три товара в обычном `List<Product>`. `ProductsController` получает сервис и `ILogger<ProductsController>` через конструктор. Итоговая регистрация — `AddScoped`. EF Core и база данных в этой лабораторной не используются.

| Метод | Endpoint | Назначение | Фактический ответ |
|---|---|---|---|
| `GET` | `/api/products` | Получить весь список | `200 OK` |
| `GET` | `/api/products/{id}` | Получить товар | `200 OK`, `400 Bad Request`, `404 Not Found`; при пойманной ошибке — `500` |

## Жизненные циклы DI

| Жизненный цикл | Время жизни | Пример применения |
|---|---|---|
| `Transient` | Новый экземпляр при каждом разрешении | Короткая stateless-операция |
| `Scoped` | Один экземпляр на HTTP-запрос | Сервис, который использует `DbContext` |
| `Singleton` | Один экземпляр до остановки приложения | Потокобезопасный общий кэш |

В текущем `Program.cs` зарегистрирован `Scoped`. В `docs/` нет отдельных доказательств запусков Transient и Singleton, поэтому не следует утверждать, что скриншотами подтверждены все три прогона.

## Обработка уровня журнала

В `appsettings.json` установлен `Default: Information`; имеющийся PowerShell-скриншот показывает `info` и `warn`. Дополнительный эксперимент с уровнем `Warning`, описанный в PDF, отдельным снимком не подтверждён.

## Контрольные вопросы

1. **Что такое DI?** — DI — это когда приложение передаёт классу необходимые сервисы, вместо того чтобы класс создавал их сам.
2. **Какую проблему решает DI?** — Сервисами управляет приложение, поэтому их проще заменить и тестировать.
3. **Что такое слабая связанность?** — Класс зависит от нужного ему интерфейса, а не от одного конкретного сервиса.
4. **Зачем нужен интерфейс?** — Он описывает доступные действия и позволяет заменить реализацию, не меняя контроллер.
5. **Что такое Constructor Injection?** — Передача сервиса контроллеру через параметры конструктора.
6. **Зачем регистрировать сервис в `Program.cs`?** — Чтобы DI-контейнер знал, какой класс использовать для интерфейса и как долго хранить экземпляр.
7. **Чем различаются Transient, Scoped и Singleton?** — Transient создаёт новый экземпляр при запросе; Scoped использует один экземпляр в рамках одного HTTP-запроса; Singleton создаётся один раз на всё приложение.
8. **Для чего нужен `ILogger<T>`?** — Он записывает сообщения в журнал и указывает, из какого класса они пришли.
9. **Чем отличаются `Information`, `Warning` и `Error`?** — Это обычное событие, предупреждение о возможной проблеме и сообщение об ошибке.
10. **Зачем нужен `appsettings.json` для логирования?** — В нём можно задать минимальный уровень и правила, какие сообщения записывать.
